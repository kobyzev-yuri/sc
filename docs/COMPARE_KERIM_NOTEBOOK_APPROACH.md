## Сравнение подхода Kerim (Colab) и текущего пайплайна шкалы

Этот документ нужен, чтобы после паузы быстро вспомнить:
- чем отличается «ноутбук Kerim» (ссылка в `kerim.txt`) от текущей реализации шкалы;
- как в каждом подходе:
  - строится шкала 0–1;

  - интерпретируются результаты.

Исходные артефакты:
- `kerim.txt` — постановка задачи и ссылка на Colab с обновлённым подходом;

## 1. Подход Kerim (по описанию из kerim.txt и Colab)

> Важное: здесь нужно дописать детали после просмотра самого ноутбука Kerim.

**Цель:** упростить/структурировать построение шкалы и отбор признаков, возможно с другими допущениями, чем в основном пайплайне.

### 1.1. Общие идеи (по переписке)

- Фокус на **построении шкалы** (0–1) и **поиске лучших признаков**.
- Часть шагов было переработано с помощью LLM, то есть:
  - часть логики может отличаться от нашей текущей реализации;
  - возможны иные формулировки признаков или метрик качества.
- В ноутбуке используется эксперимент с мастоцитами (Mast Cells), где:
  - рассматривается соотношение:
    - истинного количества клеток по ИГХ;
    - разметки (Mast Cells и Mast Cells + Mast_3cl);
    - предсказаний моделей (Модель_1 и Модель_2);
  - анализируется сохранение **тенденции** (монотонный рост) между измерениями A, B, C;
  - делается вывод, что:
    - тенденция роста сохраняется;
    - но **соотношения** и интерпретация «насколько стало хуже/лучше» в разметке/модели и ИГХ расходятся.
- **Структура данных в `MAST_GEMINI/`**:
  - Пары изображений для каждого случая:
    - `N.png` — стандартное окрашивание гематоксилин-эозин (г/э) с аннотациями:
      - **зеленым** выделены мастоциты с **явными признаками**;
      - **синим** выделены мастоциты с **не очень явными признаками**;
    - `N_игх.png` — те же мастоциты на окрашивании **ИГХ** (иммуногистохимия);
  - Примеры:
    - `1.png` / `1_игх.png` — два мастоцита с явными признаками (зеленые на г/э);
    - `2.png` / `2_игх.png` — мастоцит с не очень явным признаком (синий на г/э);
    - `3.png` / `3_игх.png`, `4.png` / `4_игх.png` — аналогично.

### 1.2. Построение шкалы (как предполагается в ноутбуке Kerim)

- Как обеспечивается интерпретируемость:
  - есть ли явные пороги (границы стадий);
  - есть ли карты важности признаков?

*(заполнить после просмотра ноутбука, ориентировочная структура)*:

## 2. Текущий пайплайн шкалы (scale/ + docs/analyze.ipynb)

Ниже — краткое резюме по тому, что описано в корневом `README.md`, `docs/analyze.ipynb` и модулях `scale/`.

### 2.1. Общая структура

- **Агрегация признаков**:
  - модуль `scale/aggregate.py`:
    - сбор предсказаний из JSON по WSI;
    - расчёт count/area по каждому типу патологии;
    - создание относительных признаков:
      - `relative_count = count / Crypts_count`;
      - `relative_area = area / Crypts_area`;
      - `mean_relative_area = relative_area / count`;
    - выбор подмножества колонок (важные признаки).
- **Препроцессинг и EDA**:
  - `scale/preprocessing.py`, `scale/eda.py`:
    - StandardScaler;
    - поиск высоко коррелирующих признаков и удаление избыточных;
    - визуализации, UMAP, тесты.
- **Кластеризация и шкала**:
  - `scale/clustering.py` — HDBSCAN и др. + метрики качества;
  - `scale/pca_scoring.py` — базовая шкала на основе PC1:
    - обучение PCA, получение PC1;
    - нормализация в [0, 1] (`PC1_norm`);
    - loadings для интерпретации;
  - `scale/spectral_analysis.py` — спектральный анализ:
    - проекция на PC1, поиск мод через KDE;
    - перевод в спектральную шкалу 0–1 с буферными зонами по процентилям (P1/P99);
  - `scale/cluster_scoring.py` — маппинг кластеров на шкалу:
    - методы: spectrum projection, pathology_features, pc1_centroid, expert_labels, distance_from_normal.
- **Дашборд**:
  - `scale/dashboard.py` — единая точка работы с данными/шкалой/кластерами.

### 2.2. Построение шкалы 0–1

- Базовый путь:
  - вычислить PC1 по нормализованным признакам (StandardScaler + PCA);
  - нормализовать PC1 в интервал [0, 1] на основе процентилей:
    ```text
    PC1_spectrum = (PC1 - PC1_p1) / (PC1_p99 - PC1_p1)
    ```
  - завести интервальную классификацию (normal/mild/moderate/severe) по диапазонам спектральной шкалы.
- Расширенный путь:
  - спектральный анализ:
    - поиск мод плотности;
    - привязка мод к стадиям заболевания;
    - устойчивость к выбросам за счёт порогов P1/P99.
- Кластерный путь:
  - сначала кластеризация (HDBSCAN и др.);
  - затем маппинг кластеров на шкалу несколькими способами (включая спектральный).

### 2.3. Поиск и отбор признаков

- В `scale/aggregate.py` — базовый фильтр по осмысленным патологиям (Mild, Dysplasia, Neutrophils, Paneth и т.д.).
- В `model_development/feature_selection_automated.py`:
  - реализованы методы:
    - forward selection, backward elimination;
    - positive_loadings (по знаку/величине loadings PC1);
    - mutual_information;
    - lasso;
    - RFE;
  - комбинированные сценарии: forward+backward, MI+forward и др.
- В `model_development/analyze_score_weights.py`:
  - перебор весов в формуле:
    ```text
    Score = w_sep × separation + w_mod × mean_pc1_norm_mod + w_var × explained_variance
    ```
  - анализ чувствительности и поиск «стабильных» признаков.

## 3. Сравнение подходов (Kerim vs текущий)

> Пока часть по Kerim будет общей (без кода из ноутбука).

### 3.1. Концепция шкалы

- **Kerim (Colab)**:
  - акцент на интерпретации **динамики по конкретным клеточным популяциям** (пример с мастоцитами);
  - анализируется, сохраняется ли **тенденция** (монотонный рост/ухудшение) между измерениями;
  - потенциально может использовать более простую/прямую формулу шкалы, завязанную на конкретную популяцию клеток или несколько ключевых признаков.
- **Текущий пайплайн**:
  - мультипризнаковая шкала:
    - множество типов патологий;
    - относительные признаки (count/area, нормировка по криптам);
  - использование PCA/спектрального анализа:
    - обобщённая латентная ось тяжести (PC1/спектр);
  - отдельные инструменты для сравнения наборов признаков и методов построения шкалы.

### 3.2. Работа с признаками

- **Kerim**:
  - сильный фокус на **одном классе (Mast Cells)** и тщательный разбор примером;
  - вопрос: насколько соотносятся разметка, модель и ИГХ по динамике и абсолютным значениям.
- **Текущий пайплайн**:
  - систематический автоматизированный подбор признаков:
    - различные методы feature selection;
    - метрики качества (Score, Separation, Mod, Explained variance);
  - акцент на устойчивости к добавлению/удалению слайдов и на воспроизводимости экспериментов.

### 3.3. Интерпретируемость и калибровка

- **Kerim**:
  - интерпретация через конкретные клинические сценарии (A → B → C по мастоцитам);
  - ключевой критерий — совпадает ли **логика изменения состояния пациента** между измерениями.
- **Текущий пайплайн**:
  - интерпретация через:
    - loadings PCA (вклад признаков);
    - моды спектра;
    - визуализации в дашборде.
  - калибровка через выбор процентилей/мод (P1/P99 и границы normal/mild/moderate/severe).

## 4. Рекомендации по объединению идей

1. **Вшить сценарий с мастоцитами в текущий пайплайн**:
   - собрать данные по Mast Cells (и, при необходимости, другим популяциям);
   - прогнать их через текущую шкалу (PCA/спектральная) и проверить:
     - сохраняется ли монотонность по оси тяжести между A/B/C;
     - насколько шкала согласуется с ИГХ‑истиной.
2. **Добавить «кейс‑тесты» в experiments**:
   - сформировать небольшой набор «контрольных WSI» (как A/B/C для мастоцитов);
   - использовать их как регрессионные тесты при изменении признаков/весов/методов.
3. **При просмотре ноутбука Kerim**:
   - выписать явные формулы/правила шкалы и критерии отбора признаков;
   - либо:
     - реализовать отдельный модуль `scale/kerim_scoring.py` для точного воспроизведения;
     - либо интегрировать идеи (например, специфическую нормализацию или критерий монотонности) в существующие модули.
